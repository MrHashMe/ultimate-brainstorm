# Troubleshooting: BLOCKED cards and their fixes

A BLOCKED card has a plain `say` line, the `error`, and `fix` commands. Show them to the user and stop; never work
around a BLOCKED card by running model calls yourself or by switching families. After the fix, `<entry> continue`
resumes exactly where the run stopped: finished work is never redone.

First checks for any problem:
- `UB status "<run>" --json` - what is done, running, failed and next.
- `UB doctor --json` (add `--live` to send one PONG per family) - Python, CLIs, logins, keys, detached workers.
- `<run>/logs/calls.jsonl` (one line per model-call attempt) and `<run>/logs/<job-id>.log` (stderr tail).
- `<run>/<out>.failed.md` - first line `FAMILY CALL FAILED: <reason>`.

| Symptom (card error or note) | Cause | Fix |
|---|---|---|
| `auth` for a family; "login", 401/403, "invalid api key" | the CLI is not signed in, or a key is wrong | `claude` once and sign in; `codex login`; `kimi login` (Kimi Code ignores KIMI_API_KEY); check ZAI_API_KEY / KIMI_API_KEY / KIMI_CODE_API_KEY names with `install.py doctor`. The family is marked unavailable until you log in again and run `continue` (same host or another) or `run --continue`, or retry the BLOCKED step: each detects it again |
| `network` or `sandbox_network` from a Codex host | the Codex sandbox blocks the nested model CLIs [U-8] | approve the `ub` command prefix "always" when Codex asks, or run UB with escalated permissions; or use the terminal route below |
| "Your agent stops background work before model calls finish" (the same job relaunched 3 times) | the host kills detached workers (Windows job objects, Codex sandbox, IDE terminals) [U-24] | run `<runner> run --continue "<run>"` in a normal terminal (it asks the remaining questions there), or raise the command timeout (references/hosts.md) |
| a job failed with "killed: the worker was stopped by a signal" | the worker got SIGTERM, SIGBREAK or Ctrl+C before it finished (a host or the system stopped it; `ub stop`, a redo and the kit's own relaunch of a dead job never cause this) | its fallback runs; if the step is BLOCKED, run the rest in a terminal (`<runner> run --continue "<run>"`, the card shows the exact line) or retry the step with `next` |
| stale worker / "another session is driving this run" | a previous `ub` process or worker still holds the lock or a heartbeat | where file locks work, a dead worker's claim ends with its process (the OS frees its job lock); elsewhere its marker stands only while its process runs and its heartbeat is at most 120 s old (2 x `UB_HEARTBEAT_STALE_S`, default 60); the driver lock is held only by a live `ub` process, so wait for that session (or stop it) and run `continue`; the card's `then` retries by itself. A kit 2.0.x `ub run` keeps the run while it waits at a gate: the user answers there or closes it (Ctrl+C); the card then says "a kit 2.0.x session (pid P, host) is waiting for an answer in its terminal". A card that adds "another program holds .ub/lock.json open": close that program, then the retry drives. `UB stop "<run>"` tree-kills live workers first |
| "another session took over this run; this one stopped without saving" (BLOCKED) | this process was suspended or stalled for more than 120 s and a kit 2.0.x driver took the run's `.ub/lock.json` over, or a kit 2.0.x driver took it in the instant this process rewrote its record there | run the card's `next` fix; it waits while the other driver holds the run. After `answer` or `done` the change may or may not be saved: once the other driver is done, check `ub status` and repeat it if the gate or task is still pending |
| "A redo could not move <file> to _superseded/ yet" | another program (an editor, a viewer, a sync client, an antivirus scan) has that file open | close it, then run the card's fix; the redo finishes the moves first |
| DONE card "stopped (user)" | `ub stop` paused the run | `continue` resumes it (`next` does not); tell the user nothing finished is lost |
| the stop card says "N worker(s) could not be verified (pid ...)" | the kit cannot tell whether they are its workers (`ps` is unavailable or failed, or the worker recorded no identity), so it did not kill them | check the pids (`ps -p <pid>` / Task Manager); stop the ones that are `family.py job` workers of this run by hand, then `continue` |
| "Host task <id> is in progress in another session" | another session was handed that HOST or HOST_BATCH work, or this session polled without the task's token | let it finish there; to take it over here, run the `continue` command the card names. If this session was given the task, poll with the `--lease` of its `task.done_cmd` |
| "host task <id> was taken over and accepted from another session" (BLOCKED) | this session's task was taken over with `continue`, and this session changed its files after the other session's `done` | check the named files; to run the task again, run the card's `redo` fix |
| HOST card: "<file> is still open in another program, so this done was not applied" | an editor or viewer holds a file the host task wrote, so it cannot be made durable | close it, then run `task.done_cmd` again; do not redo the task |
| kimi unavailable: "upgrade: npm install -g @moonshot-ai/kimi-code, then kimi migrate" | the legacy kimi-cli (below 2.0) is installed | install Kimi Code CLI v2 as shown, run `kimi migrate`, then `kimi login` |
| Kimi fails on Windows / "shell not found" | Kimi Code needs Git Bash on Windows | install Git for Windows, or set `KIMI_SHELL_PATH` to bash.exe |
| `.cmd` argument refused ("unsafe character"), error class `config` | an argument with a double quote, ampersand, pipe, angle bracket, caret, percent sign, exclamation mark or line break would pass through a Windows `.cmd` shim | the kit never passes free text in argv, so the reason names a path (UB_HOME, the run folder, the repository) holding such characters: move it to a plain path, then `continue` |
| `refused` / exit 7 (policy) | a job would break privacy (other vendor, web, repo reading, a prompt for another vendor that still contains repository code) or the GLM plan terms, or Codex used a tool the job does not allow | this is working as intended; change privacy only if the user wants to (`redo` from 0.3 with a new G0), or add a family that is allowed |
| seed leak ("a generator prompt contains a line from your seeds") | a seed line reached a generator prompt (for example seeds pasted into the topic) | edit the topic or seeds so the idea text is only in 00_HUMAN_SEEDS.md, then `redo` the named step |
| origin label ("a judge prompt contains ...") | one of this run's alias ids (S2-04, H-03, ...) or an origin label (`Origin: gpt`, `(origin: human)`, `strategy: S2`) reached a judge prompt; the message names the file that holds it | remove it from that file, then run the `redo` the message gives (6.1, Q.3p or 9.3: the step that prepares the judge prompts; for the architecture judges, `next`); if it repeats, report it |
| `bad_output` / exit 5 after repair | a model kept returning output that fails its contract (or a CLI printed more than its stdout cap, 12 MB for Claude and 256 MB for Codex and Kimi by default, `max_stdout_mb` in UB_HOME/families.json; that ends the job at once) | `continue` retries through the fallback family (PROVISIONAL); if still short of the step's minimum, add a family or `redo` the step |
| `refused` / exit 7 `codex used <type> on a tools=... job` for an item type the kit does not know | a newer Codex emits a new JSONL item type | if it is harmless, add it to `backends.codex-cli.allow_items` in UB_HOME/families.json; tool types can never be allowed |
| step short of `min_ok` | too few jobs succeeded, even after fallbacks | fix the failing family (see auth/network rows) and `continue`; the card names the jobs |
| budget reached (GB) | the next job could pass `budget.max_calls` (backend requests) | reply with a higher cap, or stop; full-auto: `ub budget "<run>" --max-calls N`; `ub plan "<run>"` shows what remains |
| "kit version differs" note | the run was started with another kit version | continue normally; if a step misbehaves, `redo` it with the current kit |
| v1 run folder | 00_RUN.md without run.json | nothing to do: it is migrated on `continue` (families claude/gpt, `legacy_v1: true`; the original is kept as 00_RUN.v1.md) |
| "scripts/pipeline.json is inconsistent", or a missing or broken template | a kit file was edited or an update was cut short | `install.py update`, then `continue` |
| "path is N characters, more than the 259 Windows allows" | a deep run folder with Windows long paths off | start the run with a shorter `--root`, or enable long paths (`ub doctor` shows `long_paths`), then `continue` |
| "the run folder <path> holds '$' ..." (or a backtick or a double quote) | bash and PowerShell change that character inside the double quotes of every card command | start the run with `--root` in a folder without it; for an existing run, move its folder or resume it in a terminal with the `run --continue` fix the card shows |
| "... starts with the command word stop (continue, status, doctor), and the rest is not a run folder" | the topic begins with a command word | start again with a mode word first (`standard stop smoking coach ...`); to stop or continue a run, give its folder name |
| python not found / WindowsApps stub | `python3` on Windows is often the Store stub | use `py -3`; install Python 3.9+ with `winget install Python.Python.3.12` |
| mermaid diagrams not drawn in index.html | offline, jsDelivr blocked, the pinned Mermaid 11.17.2 build no longer matches its SRI hash [U-26], or the page's Content-Security-Policy blocked it [U-60] | the source text stays visible; open the file online, or read PROPOSAL.md; after a kit update run `ub render <run>` again |
| `ub export --format docx` does nothing | pandoc is not on PATH | install pandoc, or use index.html / PROPOSAL.md |
| lint FAIL remains after the fix pass | the architecture or proposal still breaks a lint rule | the proposal gets one automatic second fix pass (13.6b); what is left is listed at G13 (architecture items also in the proposal's open questions); `changes: <what>` at G13 runs one more fix pass |
| ONE-PAGER.md disagrees with PROPOSAL.md (lint P11) | a fix changed a figure or date in the sections but not in the one-pager | 13.6b reprints the one-pager; if the G13 card still lists P11, reply `changes: fix the lint items` |

Windows notes: Claude Code runs UB in Git Bash or its PowerShell tool; Codex in PowerShell; Kimi Code needs Git Bash.
All templates and prompts are ASCII, every free-text answer goes through an answer file and the kickoff text through
brainstorm/.kickoff.txt, so PowerShell 5.1 quoting and encodings never touch the user's words.

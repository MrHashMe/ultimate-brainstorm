# Troubleshooting: BLOCKED cards and their fixes

A BLOCKED card has a plain `say` line, the `error`, and `fix` commands. Show them to the user and stop; never work
around a BLOCKED card by running model calls yourself or by switching families. After the fix, `<entry> continue`
resumes exactly where the run stopped: finished work is never redone.

First checks for any problem:
- `UB status "<run>" --json` - what is done, running, failed and next.
- `UB doctor --json` (add `--live` to send one PONG per family) - Python, CLIs, logins, keys, detached workers.
- `<run>/logs/calls.jsonl` (one line per model-call attempt) and `<run>/logs/<job-id>.log` (stderr tail).
- `<run>/<out>.failed.md` - first line `FAMILY CALL FAILED: <reason>`.

| Symptom (card error or note) | Cause | Fix |
|---|---|---|
| `auth` for a family; "login", 401/403, "invalid api key" | the CLI is not signed in, or a key is wrong | `claude` once and sign in; `codex login`; `kimi login` (Kimi Code ignores KIMI_API_KEY); check ZAI_API_KEY / KIMI_API_KEY / KIMI_CODE_API_KEY names with `install.py doctor`. The family is marked unavailable for the run until `continue` re-detects it |
| `network` or `sandbox_network` from a Codex host | the Codex sandbox blocks the nested model CLIs [U-8] | approve the `ub` command prefix "always" when Codex asks, or run UB with escalated permissions; or use the terminal route below |
| "Your agent stops background work before model calls finish" (the same job relaunched 3 times) | the host kills detached workers (Windows job objects, Codex sandbox, IDE terminals) [U-24] | run `<runner> run --continue "<run>"` in a normal terminal (it asks the remaining questions there), or raise the command timeout (references/hosts.md) |
| stale worker / "another session is driving this run" | a previous `ub` process or worker still holds the lock or a heartbeat | wait for the heartbeat to go stale (60 s for workers, 120 s for the driver lock) and run `continue`; `UB stop "<run>"` tree-kills live workers first |
| kimi unavailable: "upgrade: npm install -g @moonshot-ai/kimi-code, then kimi migrate" | the legacy kimi-cli (below 2.0) is installed | install Kimi Code CLI v2 as shown, run `kimi migrate`, then `kimi login` |
| Kimi fails on Windows / "shell not found" | Kimi Code needs Git Bash on Windows | install Git for Windows, or set `KIMI_SHELL_PATH` to bash.exe |
| `.cmd` argument refused ("unsafe character") | an argument with a double quote, ampersand, pipe, angle bracket, caret, percent sign, exclamation mark or line break would pass through a Windows `.cmd` shim | report it; the kit never passes free text in argv, so this points at a path containing such characters: move the project to a plain path |
| `refused` / exit 7 (policy) | a job would break privacy (other vendor, web, repo reading) or the GLM plan terms | this is working as intended; change privacy only if the user wants to (`redo` from 0.3 with a new G0), or add a family that is allowed |
| seed leak ("a generator prompt contains a line from your seeds") | a seed line reached a generator prompt (for example seeds pasted into the topic) | edit the topic or seeds so the idea text is only in 00_HUMAN_SEEDS.md, then `redo` the named step |
| origin label ("a judge prompt contains an origin label") | an alias id (S2-04, H-03, ...) or the words origin:/strategy:/generated by reached a judge prompt | rerun the named step with `redo`; if it repeats, check pool files for alias ids inside idea text and report it |
| `bad_output` / exit 5 after repair | a model kept returning output that fails its contract | `continue` retries through the fallback family (PROVISIONAL); if still short of the step's minimum, add a family or `redo` the step |
| step short of `min_ok` | too few jobs succeeded, even after fallbacks | fix the failing family (see auth/network rows) and `continue`; the card names the jobs |
| budget reached (GB) | `budget.max_calls` would be exceeded | reply with a higher cap, or stop; `ub plan "<run>"` shows what remains |
| "kit version differs" note | the run was started with another kit version | continue normally; if a step misbehaves, `redo` it with the current kit |
| v1 run folder | 00_RUN.md without run.json | nothing to do: it is migrated on `continue` (families claude/gpt, `legacy_v1: true`) |
| python not found / WindowsApps stub | `python3` on Windows is often the Store stub | use `py -3`; install Python 3.9+ with `winget install Python.Python.3.12` |
| mermaid diagrams not drawn in index.html | offline, or the CDN changed major version [U-26] | the source text stays visible; open the file online, or read PROPOSAL.md |
| `ub export --format docx` does nothing | pandoc is not on PATH | install pandoc, or use index.html / PROPOSAL.md |
| lint FAIL remains after the fix pass | the architecture or proposal still breaks a lint rule | the item is listed at G13 and in the proposal's open questions; `changes: <what>` at G13 runs one more fix pass |

Windows notes: Claude Code runs UB in Git Bash or its PowerShell tool; Codex in PowerShell; Kimi Code needs Git Bash.
All templates and prompts are ASCII, and every free-text answer goes through an answer file, so PowerShell 5.1
quoting and encodings never touch the user's words.
